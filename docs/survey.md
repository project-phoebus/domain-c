# Domain C 6.9 compiler (cc.m68k, cc.a88k) - survey for translation

Goal: regenerate the compiler's Pascal (and C/asm/Fortran) sources from the
two executables on the DOMAIN C V.6.9 cartridge, the way
`~/src/domainos-archeology/source/com/bind` was regenerated.  Original paths
`//foo/bar/baz.pas` become `./foo/bar/baz.pas` in this tree.

Generated tables (regenerate with `tools/cc_survey.py`):

- `survey-tables.md`: per binary, the makers and every unit (path, language,
  routine count, code start, A5, routine bytes, span), then the units the two
  binaries share.
- `routines-cc.m68k.md`, `routines-cc.a88k.md`: per unit, its inserts in the
  order the compiler opened them (the .blocks list reversed), then every routine (name, address, code
  length, level).

## The binaries

| file | install dir | format | .text | units | routines (.blocks) |
|------|-------------|--------|-------|-------|--------------------|
| `cc.m68k` | `ctape/install/ri.apollo.cc.v.6.9.m/` | Apollo m68k COFF (0x197) | 0x89E94 (+ opt$procedure, peephole$proc, codegen$proc) | 105 | 2170 |
| `cc.a88k` | `ctape/install/ri.apollo.cc.v.6.9.mpx/` | Apollo m68k COFF (0x197) | 0x247FF4 (+ opt$procedure) | 132 | 3368 (+ ~1080 ISC routines with no record, below) |

Both run on the 68K.  `cc.a88k` is the C compiler whose back end is the newer
`lang2/source/be_com` (with the ISC instruction selector) generating code for
the a88k (PRISM, DN10000); `cc.m68k` has the older `lang/lang/source` m68k
back end (`cg_*`, `reg_*`, `emit`, `final`, `outbin`, ...).

Makers (`.mir`), the same in both: ld 7.11, bind, **C compiler PRISM=>68K Rev
6.89(586)**, ASM, **Pascal compiler PRISM=>68K Rev 8.89(549)**, **Pascal
compiler 68K Rev 8.89(546)**, **Fortran 77 compiler PRISM=>68K Rev
10.89(615)**.  Note Pascal Rev 8.89, a generation after SR10.2's 7.x that
dpc models (see "Pilot").

Languages: m68k 100 Pascal, 3 C (`c_initdate.c`, `c_run_acpp.c`,
`us1/us1/lib/dblib/loc/src/loc_build.c`), 1 Fortran (`lang2/source/ftn/source/const_op.ftn`), 1 assembly
(`lang/c_compiler/source/c_data.asm`, 18 KB in .text, no routine records).

Shared: 81 units are in both; 78 have identical routine names and lengths
(differing: `opt_strength.pas` 59 vs 12 routines, `cargs.pas`, `iosub.pas`
lengths).  The front end (`lang/c_compiler`, `lang/common`, most of
`lang/lang` outside the code generator, `lt_utils`) is translated once and
checked against both binaries.  m68k only: 24 `lang/lang` code generator
units.  a88k only: `be_com/*`, `isc/*`, the generated `isc_*` units,
`exs.pas`.

## .blocks version 4 (what the tool patch handles)

`tools/coff_compare.py` is a patched copy of
`source/domain_os/tools/coff_compare.py` (merge back when done; it imports
the rest of that tool chain from `$SOURCE_TOOLS`, default
`~/src/domainos-archeology/source/domain_os/tools`).

- Unit header `01 00 01 04` (SR10.2 binaries: `01 00 01 02`); same fields:
  +8 block count.w, +0xA first block.l, +0xE file record.l, +0x12 timestamp
  record.l, +0x16 length.l.  Most units are v4; `c_data.asm` is v2.  Units
  follow at 4-byte alignment.
- Block records keep v2's fields (+2 kind, +4 sibling, +8 child, +0xC name,
  +24 code length.l, +28 cell.w, +30 offset.l) but are variable length; the
  links are followed, so that does not matter.  Every v4 block's cell is 4.
- File record (tag 0x02, count.w, cells): .lines address, .unwind address,
  **an offset, not an address** (0x3190, 0x9FB4, ...: in cc.a88k it falls
  inside .text's range and the old code took it for a code start), the code
  start, the A5 when the unit has data, then the other data sections the
  unit uses (cc.a88k's back end: the operand and instruction tables).
- String record (0x1B, length.l): v4 lists **every file the unit read**,
  NUL-separated, the inserts in **reverse order of opening** (newest
  first) and the unit's own source last.  Evidence: in every unit that
  reads `/sys/ins/base.ins.pas` it is the last of the customer inserts
  (`c_expr_sem.pas`: fpp, error, pfm, base), and std.pas's DIAG_ insert
  is read without base (diag.pas: diag.ins, std.ins, base, vfmt once
  reversed); then a timestamp record (0x03, count.l, (time.l, name offset.l)
  pairs).  v2 (`c_data.asm`): the path then the module name, and the record
  comes after the block records.

## Open items

1. **ISC routines without records (cc.a88k).**  0xF0B02..0x18C588 (622 KB,
   ~563 `link`/`rts`) and 0x18C7A0..0x20042C (463 KB, ~518 `link`) hold code
   that no .blocks record names, inside the generated units
   `isc_pass_1_main.pas` / `isc_pass_2_main.pas` (sources under
   `//moon_unit/isc_prism_dervobjs/dseeaggs/iscg_input/`, DSEE derived
   objects: generated by the ISC generator from the `iscg_input`
   description).  Names may come from .lines, the generator's own patterns
   or nowhere.  `isc_debug` has one 92 KB routine and `isc_pattern_matcher`
   a 31 KB one: generated too.
2. **Pascal Rev 8.89 code generation vs dpc** (the pilot;
   `rev889-patterns.md`).
3. **Private inserts.**  `//us/us/sys/ins/*` are the customer inserts (in
   the SR10.2 install); `//us/us/ins/*` and the compiler's own
   (`globals*.ins.pas`, `c_*.ins.pas`, `cg.ins.pas`, ...) must be
   reconstructed, as bind's were.  One is a DSEE derived object
   (`glob_extern.ins.plb.pas` from `glob_extern.ins.pas`).
4. The unit with no code at all in cc.m68k is `opinfo.pas` (data only);
   `empty.pas` and `std_lib.pas` have a span but no routine records.

## Pilot: `lang/c_compiler/source/c_get_rlen.pas`

`pilot/c_get_rlen.pas` (types inlined; the real unit opens 25 inserts) for
`get_rlen` (0x0532D8, 0x7C bytes).  dpc's code is the image's but for the
prologue: the image has `pea (A5); lea 0x142524,A5` and the epilogue's
`movea.l (-8,A6),A5`, though the routine never uses A5; dpc leaves A5
alone.  The body (the case as a compare chain, the result kept in D0, the
otherwise's if chain) is byte-identical.

Rev 8.89 forms seen so far that dpc does not produce: see
`rev889-patterns.md`.  Byte-identical output needs a dpc "Rev 8.89"
profile; without it dpc's best-effort mode compiles correct but not
identical code, which is the mode this translation uses (decided
2026-11-10).
